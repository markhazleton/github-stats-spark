# repositories.json Contract Revision

## Scope

This contract defines the additive repository record changes required for the unified dataset generated by `spark unified`.

## Versioning

- Current schema version: `2.0.0`
- Planned schema version after implementation: `2.1.0`
- Compatibility expectation: additive only; existing fields remain intact

## Repository Record Additions

Each repository entry in `repositories[]` MUST include the following objects.

### pull_request_summary

```json
{
  "availability": "available",
  "reason": "none",
  "has_open_pull_requests": true,
  "total_open": 4,
  "draft_count": 1,
  "review_requested_count": 2,
  "oldest_open_age_days": 17,
  "source": "rest.pulls.list"
}
```

### security_summary

```json
{
  "availability": "partial",
  "reason": "permission_denied",
  "overall_state": "warning_present",
  "feature_status": {
    "advanced_security": "unavailable",
    "secret_scanning": "unavailable",
    "secret_scanning_push_protection": "unavailable",
    "dependency_alerts": "enabled",
    "automated_security_fixes": "enabled"
  },
  "active_alert_counts": {
    "total_open": 3,
    "critical": 1,
    "high": 1,
    "medium": 1,
    "low": 0
  },
  "sources": [
    "rest.repos.vulnerability-alerts",
    "rest.repos.automated-security-fixes",
    "rest.dependabot.alerts"
  ]
}
```

## Field Semantics

### availability

- `available`: the enrichment domain was collected successfully
- `partial`: some signals were collected, but one or more planned sources were unavailable or failed
- `unavailable`: no trustworthy enrichment result was collected

### reason

- `none`: no collection issue applies
- `permission_denied`: token or caller visibility prevented access
- `api_error`: GitHub returned an operational failure
- `not_supported`: the source or repository context does not support the signal
- `not_requested`: collection was intentionally skipped
- `unknown`: fallback bucket for an unclassified problem

## Contract Guarantees

- `pull_request_summary` MUST be present for every included repository.
- `security_summary` MUST be present for every included repository.
- Missing data MUST be represented inside the enrichment object, not by omitting the object.
- Existing repository fields such as `name`, `stars`, `commit_history`, `commit_metrics`, and `tech_stack` MUST remain unchanged.

## Consumer Guidance

- Consumers should branch on `metadata.schema_version >= 2.1.0` before depending on the new fields.
- Consumers must treat `availability = partial` as a valid, displayable state rather than a hard failure.
- Consumers must not interpret `unavailable` as equivalent to zero warnings or zero open pull requests.
