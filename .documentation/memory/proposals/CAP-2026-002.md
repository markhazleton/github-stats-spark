## Current State

No existing principle covers how tooling (audits, security scanners, linters) should treat **generated and built artifacts** in the repository. The Documentation Standards section identifies `docs/` as "GitHub Pages publishing source" and `output/` as generated output, but provides no guidance for quality gates or CI tooling that scans the entire repo indiscriminately.

## Evidence

### Pattern Analysis

Two audits flagged the same root cause: quality and security scan tooling treats generated/compiled JavaScript files in `docs/assets/` and `htmlcov/` as source code, producing false positives and degrading signal quality.

| Audit 2026-03-29 (OBS1, carried forward HIGH) | "Noisy/non-actionable security findings" from generated paths explicitly cited under Principle III (Fail Fast, Fail Loud) compliance gap. | Principle III scored PARTIAL |

### Specific Examples

1. **Audit 2026-03-28 (OBS1, HIGH)**: Five `exec()` detections in `docs/assets/site-*.js` and `htmlcov/coverage_html_cb_*.js` — all generated/compiled artifacts. Recommendation: "Exclude generated paths (`docs/assets`, `htmlcov`, `docs/output`, `docs/data`) from source/pattern scans."
2. **Audit 2026-03-28 (OBS1 → Principle III PARTIAL)**: Noisy findings directly degraded Fail Fast, Fail Loud compliance score despite no actual violations in source code.
3. **Audit 2026-03-29**: Principle III carried forward as PARTIAL due to non-actionable scan output — the root cause was unexcluded generated paths.

## Proposed Change

### New Principle: VI. Generated Artifact Boundary

> Repository build outputs and coverage artifacts are **not source code** and MUST be excluded from source-code quality gates.
>
> **MUST Requirements:**
> - The following paths MUST be excluded from all source-level security and quality scans: `docs/assets/`, `docs/data/`, `docs/output/`, `htmlcov/`, `output/`, `MagicMock/`, `preview/`, and any path matching `*.min.js` or `*.map`.
> - CI security scanners (pip-audit, npm audit, pattern-based secret detection) MUST target only maintained source trees: `src/`, `frontend/src/`, `config/`, `.github/`.
> - Audit reports that surface findings exclusively from generated paths MUST label those findings as `NOISE - generated artifact` rather than code violations.
>
> **SHOULD Recommendations:**
> - Maintain an explicit exclusion list in `config/spark.yml` under a `scan.exclude_paths` key so tooling and humans share a single source of truth.
> - When adding new generated output directories, update the exclusion list before the first scan run.

**Rationale**: The constitution already declares `docs/` as "deployment/source artifacts, not documentation content" (Documentation Standards), yet no boundary exists for *tooling behavior*. The gap cost two consecutive audits their Principle III compliance rating despite zero actual source-level security violations. An explicit Generated Artifact Boundary principle eliminates this recurring false-positive pattern, ensures audit signal is trustworthy, and aligns scanning tools with the documentation boundary already in the constitution.
